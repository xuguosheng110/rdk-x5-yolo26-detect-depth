# GS130WI 三模式验证记录

日期：2026-09-11。设备：RDK X5 V1.0 / RDK OS 3.5.0 / Ubuntu 22.04 / Linux 6.1.83，DNN 1.24.5、HBRT 3.15.55，GS130WI、480×320 SPI / Goodix 触摸、Firefox kiosk。

## 已验证

- 两路 SC132GS 被驱动识别并持续出图；UNION EEPROM 可读取。主路 1280×1088、StereoNet 子路 320×256，请求 15fps。
- YOLO 检测与单目深度、官方 StereoNet、官方人体与年龄三种工作负载能够切换；停止旧进程组后才启动新组。进程检查未发现三套模型同时运行。
- 浏览器左右显示检测/深度与双目原图/深度，PC 随窗口等比例放大；480×320 SPI 页面全屏，底部保留三个按钮。
- 人体渲染以官方原始人体消息为主，保留人体、人脸、头部、手部框与关键点，再按 track_id 合并 face_age_detection 的年龄。年龄节点输出不能替代完整人体消息。
- C++ 构建、CTest 3/3；新增 Python 语法检查、安装脚本 Bash 语法检查通过。
- 六次连续真实切换通过：每次检查新模式、代次变化、JPEG 签名、新帧计数增长、人体 AI 消息或 YOLO 两项计数。非法模式 400、跨站请求 403、并发切换 409。
- 最终配置重启后 camera / bridge / mode / portal 均自动运行，sunrise 的 Firefox 自动进入 kiosk；随后再次六次切换通过。冷启动阶段仍需等待相机初始化，不能把服务 active 等同于已经出图。

## 性能观测与修正

| 项目 | 调整前 | 调整后观测 |
|---|---|---|
| 人体显示桥接 | 约 1.4fps，Python 单核约 100% | 约 8–9fps，使用 ROS 原生字节数组、OpenCV 单线程 |
| StereoNet 日志端到端延迟 | 大图缩放路径约 125–130ms | 320×256 子码流约 78–84ms，算法约 15fps |
| 常规算法切换 | 曾因相机订阅退出后停帧 | 图像桥接常驻后约 5–8 秒，连续切换通过 |

观察窗口与场景有限，这些是当前板端输出/日志数据，不是 PC 实际呈现 FPS、网络延迟或 SPI 物理刷新率，也不是最低性能保证。第一次冷启动期间的切换约 19 秒，包含相机初始化。

主要改动：用 `array.array('B')` 避免每帧约 78 万个字节的 Python 校验；关闭 StereoNet 默认逐帧保存；使用模型尺寸子码流，避免此版本大图路径重复缩放内参；常驻图像订阅，减少模式切换对相机采集的影响。

## 未通过或未覆盖

- **双目测距精度未通过验收**：左右图像特征匹配仍有明显垂直偏差；图像出图和内参重复缩放修正不能替代模组标定。页面明确标注距离暂不作测量依据。需要固定相机、核对左右路与 EEPROM 标定对应关系，用标定板与已知距离重新验收。
- **性别未实现**：当前安装的官方人体、年龄模型没有返回性别。不能因通用 Attribute 消息定义中列有 gender 示例就声称模型支持该能力。
- 年龄模型曾实机输出人脸年龄标签；未评估年龄准确率。当前最终画面主要朝向天花板，没有完成修订后全身动作、遮挡、多人的关键点视觉验收。
- Goodix 设备可识别；浏览器按钮与跨端同步已验证，但未远程证明实际手指触控命中率。
- 无长时间压力、不同模组、不同屏幕的兼容性保证。
